## 经验（以后遇到同类任务可直接复用）

- 判断"配置是否一致"时，**仓库文件不是事实来源，运行实例配置才是**。凡是"某脚本会写运行配置"
  的场景，都要检查"重跑这个脚本会不会把别人后来手改的东西覆盖掉"——这类静默回退没有任何报错，
  是最难发现的一类岔子。
- 插件类配置里，除了用户可见的 `proactive_prompt`，还要看 `context_settings.*_prompt` 这类
  "附加指令块"。它们往往比主提示词更晚进入上下文，实际影响可能更大，且最容易长期没人审。

### 修订后的模型（记住这套，别再混）

- **两个 ID**：`fingerprint`（sha256 全量，判"是否同一句"）+ `occurrence_id`
  （`<fp>__<时间戳><rand4>`，判"哪一次"）。文件名/ack/队列用后者；窗口/重现/补扫去重用前者。
  **不用自增序号**——文件被手工删或锁失效时序号会撞，撞了就是覆盖。
- **`ack_state` 与 `resend_state` 正交**：`acked` 只由 `alert_ack.py` 写，**超时逻辑禁止触碰**；
  `exhausted` 只表示停止自动提醒，措辞统一「已停止自动提醒（未确认）」。
  重启分四支，**已过全部 slot 直接转 exhausted、不补 3 次**（关机两天后连发 3 条叫骚扰）。
- **问句次数 `safety_ask_count ≤ 2`**：槽位 #1 即时层 / #2 后续层。布尔（`inline_asked`）不够用——
  布尔记不了"问了几次"，而次数才是防重复问的唯一依据。
- **对话侧计数与告警侧 ack 不互相推导**：告警被 ack ≠ Miruku 可以再问；Miruku 问过 ≠ 告警被确认。
- **同指纹 30 分钟节流 = 延后不丢**（`push_due_at`），只约束同句重复，不吞新事件。
