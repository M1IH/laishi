## 危机告警 v5：补 A 档首次发送失败的时钟（Codex v4 复核阻断项）

- Codex 复核（`docs/crisis-alert-v4-review-20261022.md`）：B 档 `failed_final` 方案**通过**；但 A 档"首次传输失败 → `pending` + `resend_state = active` + 从 `first_pushed_at` 算 +15/+30/+45"是**算不出时间**的组合——首次失败时 `first_pushed_at = null`，起点不存在。
- **两种必然的错误落法**（写进 §7.9 开头表格）：拿 `occurred_at` 顶替 → 一创建就"逾期"，每轮扫描都判该补发，按分钟级狂发；严格求值遇 `null` 跳过 → **永不触发**，通道恢复也不发。
- **解法：拆成两个时钟**，入口只判 `first_pushed_at`。
  - 时钟①传输重试（仅 A 档）：`transport_retry.next_retry_at` 驱动，退避 60s/180s/600s/1800s/**3600s 封顶**，不设总次数上限，`resend_count` 恒 0，`resend_state = none`，**没有终态**。
  - 时钟②提醒补发（首次成功后）：`next_resend_at` 驱动，3 slot 从 `first_pushed_at` 起算。
- **规则 4「写前推进」是关键**：每次尝试前先把 `next_retry_at` 写未来并落盘再发——否则崩溃+重启会对着"已到期的过去时刻"无限狂发。**光加字段不够，必须写消费侧行为**（与 v4 的 `failed_final` 同一教训）。
- 新增判损坏：**`first_pushed_at = null` ↔ `resend_state = active` 互斥**；重启时 `first_pushed_at = null` 的事件**不得**进 §7.6-5 任何分支，尤其不得因"过 slot"转 `exhausted`（转了=永久静默）。
- 提醒补发失败：**消耗 slot 不追补**（追补会在通道恢复瞬间连发 2–3 条，比少提醒一次更像刷屏）；`reminder_failed_count` 单独计数，`push_state` 保持 `sent`；3 次全失败 → `exhausted` 不是 `failed_final`。
- `failed_final` 措辞按 Codex 意见改为**"未成功且按规则不再尝试"**——`target_check` 根本不该尝试 QQ，"已尝试"不成立。**终态描述的是"到此为止"，不是"试过了"。**
- T16–T19 + 第三条演算链（首次失败→重启→仍失败→首次成功→三次补发），给三个必验数字：首次成功前 `resend_count` 必须 0；`next_resend_at` 必须按 `first_pushed_at` 算；重启后必须仍 `pending`+`none`。验收 23→27。
