# WB-07 初稿复核（2026-10-22，Codex）

## 结论

四类按对话动作区分、情绪优先、20 条匿名样例及离线验收框架有用；**需小范围补件后通过**。本稿不能直接把所有可接受示例当成上线目标回复。

## 必须补件

1. **约局不能承诺未具备的参与能力。** B1 的「来」、B4 的「行」「你先开」会让来世以为 Miruku 能进入游戏；B2 才说「上不了」，同一类自身矛盾。请区分“能在聊天里陪聊/出主意”与“能进入 Oopz、游戏或实体机”；示例一律如实回应，不反复强调 AI 身份，也不把明确的邀请含混答应。对照 `prompts/system.txt` 第 13、15 行的能力与现实经历边界。
2. **A/D 分界不能只看句子里有具体对象。** X1「在打什么歌」可能是在问 Miruku 此刻在打哪首，此时并无与 Miruku 状态无关的客观答案，不应一律判 D。请改写 X1 或增加“问的是曲目事实还是 Miruku 当前行为”的判据，并同步修订 §1.1、§1.2、§1.4 的绝对说法。
3. **知识示例不能把未经核实的事实写成标准答案。** D1/D2/D3/D4 的具体玩法、难度、名称若非从已核实知识条目取得，应改为占位或注明仅示意，离线验收应检查答案与知识源一致，不能只查“答了一个具体词”。V1 的“D 类 4 条全部注入”也过强：知识库无条目或事实未核实时，正确行为是坦诚不确定，不应强制注入。
4. **等待感的决策范围需写准。** 当前已拍板删除的是主动文案中的“等待感/想念/轻微失落”。§4.1 将其直接推为所有被动回复都禁止，并写“库内指令优先级高于提示词”，这两句都缺依据。可保留“该条目在被动问候时造成自述/等待感”的风险，但不要把跨场景禁止写成 OTTO 已拍板；若建议改 `knowledge/`，列为建议，交 DeepSeek 复核。§八 D4 不宜要求 OTTO 重拍一个已定的主动文案决定。

## 非阻断提醒

- A 类一方面绝对禁止「不用睡觉」，X4 又允许它；可定义为“普通寒暄禁主动解释，明确问为何一直在线时简短如实回答”，并同步 §2-A、V5。
- `A/B/C 0 注入、D 必注入` 可作为样例目标，不能作为所有真实语料的硬统计目标。混合句和检索无结果应允许“无注入但答得对”，否则会催生误注入。
