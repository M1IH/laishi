# 首次基线分数（tone_score v1.1，2026-11-10 重算）

> 原始版本：2026-11-07　**本文件于 2026-11-10 重写**，原因是原版有两处口径错误，数字不可用。
> 工具：`data/tone_score.py`（v1.1）　规范：`docs/tone-rubric-spec.md` v1.0（已定稿）
> 语料：服务器容器 `data_v4.db` 全量导出

## 零、为什么要重写

原版（2026-11-07）报出「最近 100 回合 76 分 B、句号率 7.0%」，这两个数字都是错的，差错来自两处口径：

**错误一：按「回合」计，没有按「实际发出的消息」计。**
AstrBot 的发送层会把一条回复按换行拆成多条 QQ 消息（`cmd_config.json` → `platform_settings.segmented_reply`：`enable=true`、`words_count_threshold=150`、`split_mode=regex`、`regex="\A.*?(?:\n|…+)|(?<=\n).*\Z|(?<=…).*\Z|.+\Z"`）。模型写的「躺着呢\n\n趁你上课，我偷会儿懒」在用户那边是**两条消息**，不是一条带空行的长消息。
真人基线（`persona/tone_profile.md` 的 9,380 条）本身是按**一条消息**统计的，所以按回合把两段拼起来算，会系统性高估长度和指标偏离。

**错误二：`conversations.content` 有 235 条是 segment 列表的 repr 字符串。**
形如 `"[{'type': 'text', 'text': '就是感觉…'}, {'type': 'text', 'text': ''}]"`，早期导出直接 `str()` 取值，导致旧段 1,015 个回合里有 **212 个的正文是这串 repr 原文**（整段 `[{'type': ...}]` 被当成一句话）。它同时污染了长度分布和句号率（repr 里的字符串自带引号与逗号）。
修复：`normalize()` 对 str 型 content 依次 `ast.literal_eval` → `json.loads`，重跑后 `str_repr_recovered=531`、污染 0。

两处合起来的效果：原版把 76 分、13% 句号率当基线，而**同一批数据按条重算，句号率是 4.5%、最近 109 条是 2.8%**。评分工具本身没有 bug，是喂给它的数据形状不对。

C3 的成因已查明：`cmd_config.json` 里 `provider_settings.default_image_caption_provider_id='deepseek/deepseek-flash'`、`provider_ltm_settings.image_caption=true` —— 图片先被转成文字描述再喂给模型，模型于是顺着描述去点评画面。**这是配置层的口子，不是人格没写。**

## 四、原版「下一步优先级」的更正

原版列的五条里，第 1、2、3 条的前提都被推翻了：

1. ~~句号率 7.0% → ≤1%（D2 最大扣分）~~ —— **句号率实际是 4.5%，且 v2 上线后已降到 0.0%**。原版说的「prompt 里没有任何关于标点的约束」也不准确：`prompts/system.txt` L5 明确写了「平常用自然的短句，通常不加句号」。
2. ~~≤10 字占比 47% → ≥85%~~ —— v1 实测 48.4%，v2 普通回复已提到 **69.3%**，方向对但没到目标。
3. ~~中位 11 → ≤6 字~~ —— v2 已到 **9 字**。
4. C3「这张」类表述 11 次 —— 成立，但根因是图片 caption 配置（见上）。
5. D4/D5 已接近满分 —— 成立。

**真正的当务之急换成了主动消息**：v2 上线后普通回复明显变短（中位 9 字），但主动消息反而变长了（中位 17 字、≤10 字仅 5.9%），因为 `friend_settings.proactive_prompt` 在 **2026-10-28 15:23** 从 454 字被换成 276 字，把「只发一条短消息，通常十个字上下，最多二十来字」整段删掉了。该问题已于 2026-11-10 修复（补回长度约束与主语规则，现 432 字）。

## 五、复现方式

```bash
# 1. 在容器里导出（会做 repr 还原、按发送层正则展开分条）
docker exec astrbot python3 /tmp/export_v2.py /tmp

# 2. 取回本地
docker cp astrbot:/tmp/turns_all.json .tmp-tone/turns_all.json

# 3. 按条评分
python data/tone_score.py --turns .tmp-tone/old_msgs.json
```

> 注意：`--recent` / `--limit` 是**回合**级截断，不是条级。要做「最近 N 条」的等量对照，得先按条展开再截断（见 `.tmp-tone/mk_last75.py`）。
