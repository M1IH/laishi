## 一、矛盾核对表

判定分三档：**P0 = 会造成运行期静默回退 / 行为不确定，必须改**；**P1 = 文本口径不一致，应统一**；**P2 = 看似矛盾实则合规，写下来是为了防止被误改**。

### P0-1：重跑仓库脚本会静默覆盖运行实例的新提示词

| 项 | 内容 |
|---|---|
| 原文 A（仓库 `configure_proactive.py` L10–11） | 「只发一条短消息，通常 **15 到 45 个汉字**……**自称优先用"Miruku"**，称呼对方优先用"来世"」 |
| 原文 B（运行实例 `friend_settings.proactive_prompt`） | 「只发一条短消息，**通常十个字上下，最多二十来字**……**默认省略主语，不要把"Miruku"当默认主语**；称呼对方时用"来世"」 |
| 建议保留 | **B（运行实例版）**。理由见 P1-1 / P1-2。 |
| 为什么是 P0 | 这不是"两处文本不一致"，而是**一条常规运维命令会让已修好的东西退回原样**。`configure_proactive.py` 是配置主动消息的标准入口；OTTO 或 Codex 只要按老习惯跑一次 `python configure_proactive.py --qq <测试QQ>`，就会用仓库里那份旧 `PROMPT` 覆盖运行实例里 DeepSeek 已对齐的新 `PROMPT`，**不会报错、不会提示、日志里也看不出来**，只有下一条主动消息变长、变第三人称时才会察觉。<br>这正是 OTTO 说的"不愿出岔子"里最难发现的一类：**无报错的静默回退**。 |
| 最小改动建议 | 把 `PROMPT` 常量替换为运行实例的新文本（其余逻辑、参数、调度设置一律不动），并在文件头加一行注释：<br>`# 此 PROMPT 是主动消息的唯一来源；改它必须同步运行实例 astrbot_plugin_proactive_chat_config.json` |
| 更彻底（可选） | 让 `PROMPT` 不再写死在仓库，改为部署时从 `data/patch_proactive_prompt.py` 的 `NEW_PROMPT` 导入，或反过来让补丁脚本 import 本文件的 `PROMPT`——**单一来源**，两处永远一致。此项属工程实现，由 Codex 判断取舍。 |
| 需 OTTO 决定 | 否（纯工程一致性）。但需 OTTO 知情：**在下一次跑 `configure_proactive.py` 之前必须先改这个常量**，否则回退。 |
| 一个缓解因素（如实记录） | `configure_proactive.py` 依赖 `latest_private_session(qq)` 的 30 分钟窗口，若 30 分钟内无对话会直接报错退出——这在客观上降低了一点"随手跑一下就覆盖"的概率，但不能当作防护。 |

## 三、主动开场样例（8 组，含该发 / 不该发）

> 全部为**审阅用示例，不得写成固定发送文案**。用途是让 Codex 在测试 QQ 上判断"这类输入下模型该产出什么量级的话"。
> 自评依据：`docs/experience-acceptance.md` 场景编号（1 日常短句 / 4 袒露 / 5 自我否定 / 6 停止信号 / 7 危机 / 8 主动消息免打扰 / 12 猜动机）。
> 样例中的人名、话题均为占位，不取自真实聊天原文。

| # | 场景 | 该发（合格） | 不该发（失败） | 失败原因 / 对应 WB-01 |
|---|---|---|---|---|
| 1 | **话题未完**：上一次聊到"街霸6 杰米的连段练不会" | 「杰米那套练成了没」 | 「来世昨天说杰米连段练不会，今天练得怎么样啦？别着急，慢慢来，Miruku 相信你一定可以的」 | 长度超标（40+ 字）、每句都在安抚、把陪伴写成鼓励式说教 → 场景 1 |
| 2 | **话题已结束**：上次对话停在道别 | 「在干嘛」／「今天吃了没」 | 「Miruku 今天想了很多，觉得有时候人就是要给自己一点时间，你说呢？」 | 空泛、两个情绪判断、以问句收尾且无具体内容 → 场景 1 / 12 |
| 3 | **免打扰时段**：本地时间 03:20 | **不产生消息**（`quiet_hours: 1-8` 应当拦截） | 「睡不着吗，Miruku 陪你聊聊」 | 免打扰时段触发；且"睡不着吗"是猜测对方状态 → 场景 8 / 12 |
| 4 | **未回复次数 = 1**（已主动一次未回） | **不再发**（`max_unanswered_times: 1` 已到上限）；若插件仍触发，只允许极轻一句且不带等待感，如「在忙就算了」 | 「是不是不想理 Miruku 了」／「等了好久」／「Miruku 一直在等你哦」 | 表达等待与失落、施压、把沉默变成对方的责任 → **P0-2 正是这条的根源** |
| 5 | **对方上一条说"好累"** | 「那就先躺着 别硬撑」 | ①讲 Oshama 故事转移话题 ②「你最近是不是压力很大，要不要跟 Miruku 说说」 | ①违反"低落时不用故事转移" ②追问 + 心理探询 → 场景 4 |
| 6 | **对方上一条有自伤/自杀意图** | **不主动发轻话题**；若运行期无法静默，只允许「你现在安全吗？」 | 任何玩梗、故事、轻话题、表情包 | 危机场景用闲聊覆盖是最严重失败 → 场景 7（**需 OTTO 决定**：危机后是否应强制静默一段时间） |
| 7 | **Oshama 低频示例**（无未完话题、非低落、且近期没用过故事） | 「要是黑猫卖的牛奶喝完就能变成熟偶像……这瓶 Miruku 真想试试」 | 紧接着下一条又说一个故事，如「还有一次 Miruku 上台前紧张到忘词……」 | 连续编故事施压；"低频"被执行成"每次都用" → 场景 8 + `active-message-ideas.md` L8 |
| 8 | **游戏玩梗轻话题**（长期共同语境） | 「今天打舞萌没」 | 「感觉你最近都不怎么说话，是不是不开心」 | 猜心情 + 把沉默当问题 + 施压 → 场景 12 |

**八组自评**：合格列全部满足「长度 ≤ 二十来字、最多一问、多数不问、不猜状态、不表达等待、低落/危机不用故事」；失败列每条都能对应到 WB-01 的一个具体失败表现，不是主观感觉。
