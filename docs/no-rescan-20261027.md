# 服务器免扫登录（真正免扫）2026-10-27

> 目标：机器重启、容器重建之后，**都不再需要手机扫码**。
> 结论：**已实现并实测通过**。

## 一、免扫靠两件事，缺一不可

| 要素 | 作用 | 位置 |
| --- | --- | --- |
| `ACCOUNT=<uin>` | 启动时传 `qq -q <uin>`，走"快速登录"而非二维码 | `compose.yaml` 的 napcat `environment`，值从 `.env` 的 `NAPCAT_ACCOUNT` 取 |
| `mac_address` 钉死 | NTQQ 登录态与设备指纹绑定，容器换 MAC 会让快速登录报"登录态已失效" | `compose.yaml` 的 napcat `networks.miruku.mac_address` |

### 为什么 MAC 这条是必须的

2026-10-26 实测链条：

```
23:10  扫码登录成功
23:39  docker recreate → 容器拿到新随机 MAC
       → 快速登录报「登录态已失效，请重新登录」→ 必须重扫
```

Docker 每次 `recreate` 都会给容器一个新的随机 MAC，而 NTQQ 把登录态和设备绑定。
所以**只设 ACCOUNT 不钉 MAC**，重建时照样要扫。

> 官方 `NapCat-Docker` 的 `astrbot.yml` 模板里那行注释掉的 `mac_address`
> 就是干这个的——当初没意识到它为什么在那儿，绕了远路。

### 为什么 `docker restart` 不需要钉 MAC

`restart` 复用同一个容器（MAC 不变），只有 `recreate`/`up --force-recreate`
才会换。但既然重建也要免扫，MAC 就必须钉。

> 注意：compose 的 `mac_address` **只在创建容器时读取**。
> 如果容器已经存在，光改 compose 不生效，必须 `--force-recreate` 一次。

## 三、日常操作

**这些都不需要扫码：**

```bash
docker restart napcat                  # 重启容器
docker compose up -d --force-recreate  # 重建容器
systemctl restart docker               # 重启 docker（等同开机）
重启服务器本身                          # 容器会随 docker 自启
```

**这些需要扫码：**

- 腾讯服务端判定登录态失效（异地登录、风控、长期未活跃）
- 删掉/替换了 `napcat/qq` 数据卷
- 改了 `mac_address` 或换了机器

掉线时面板顶部会显示红条「QQ 已掉线，需要重新扫码」，去 **NapCat·扫码** 页扫一次即可。
**不要靠重启容器"修复"掉线**——重启不会让失效的登录态复活，只会多花一次扫码。

## 四、出问题怎么查

```bash
# 1) MAC 是否符合配置
docker inspect napcat --format '{{range .NetworkSettings.Networks}}{{.MacAddress}}{{end}}'
grep mac_address /opt/miruku/compose.yaml

# 2) ACCOUNT 有没有传进容器
docker inspect napcat --format '{{range .Config.Env}}{{println .}}{{end}}' | grep ACCOUNT

# 3) 登录方式
docker logs napcat --since 5m 2>&1 | grep -E '快速登录|二维码|登录态'

# 4) 链路
docker exec astrbot python3 /AstrBot/data/laishi/ws_probe.py 01
```

判据速记：**日志里出现「二维码」= 免扫失败**；只有「正在快速登录」+ 无二维码 = 正常。
