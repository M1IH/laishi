## 二、根因（不是我最早猜的那个）

### 2.1 我最初猜「加别名」，但那条路是死的

第一版想法：给 `maimai/ban-ben-pai-zi` 加别名「极和将」。**实测无效**，两个原因逐层拦住：

**原因一：单字别名被跳过**

`knowledge/query.py` 的别名循环里有硬门槛：

```python
for alias in entry["aliases"]:
    an = normalize(alias)
    if not an or len(an) < 2:
        continue          # ← 单字「极」「将」在这里就被丢了
```

所以把「极」「将」加进别名或 `WEAK_ALIASES` **都不生效**。

**原因二：短语别名跨不过分隔符**

`clean_query` 会把停用词换成 `SEP`（`\x01`）：

```
clean_query("极和将是什么牌子")  →  "极\x01将\x01牌子"
segments                        →  ['极', '将', '牌子']
normalize("极和将")              →  "极和将"        ← 含「和」，qn 里没有
```

而别名匹配用的是 `an in qn`（带 `\x01` 的 clean 形式）或 `an in qn.split(SEP)`（整段相等）。**「极和将」既不是任何一段，也包含 qn 里不存在的「和」，永远匹配不上。**

实测确认：加了 6 个短语别名后，正例仍是 **7/10**，无变化。该改动已**完整还原**。

### 2.2 真正的根因

「牌子」这条**通用条目 `pai-zi` 抢了先**：

```
"极和将是什么牌子"
  → segs = ['极', '将', '牌子']
  → pai-zi 的别名「牌子」整段命中 → 17.58 分 → 注入
  → ban-ben-pai-zi 只有 5.00（n-gram 残分）→ 排第二，被截掉
```

**模型拿到的是「牌子＝段位认定挂的牌」，答不出「极牌/将牌是版本牌子」。** 这正是来世问「极和将是什么牌子」时她答「这两个我没什么印象」的原因。

## 三、修法：语境受限的双条件判据

在 `knowledge/query.py` 新增三个常量 + 一个判据函数 + `score()` 里一条前置分支。

### 3.1 判据（`_plate_context_hit`）

**两个条件，任一成立即可**，但都必须「独立成段」：

| 条件 | 例子 | 为什么安全 |
| --- | --- | --- |
| ① **牌子词 + 任一牌名** | 「极和将是什么**牌子**」→ segs 含「牌子」✓ 含「极」✓ | 普通话里「极」「将」不会和「牌子」同句出现 |
| ② **两个及以上牌名同时成段** | 「**极**和**将**有什么区别」→ 含「极」「将」✓✓ | 要求 **≥2 个**，所以「极其无聊有什么区别」只有「极」，不认 |

牌名集合：`极 極 将 將 神 舞舞 霸者 覇者`（含繁体）。
牌子语境词：`牌子 牌 プレート plate`。

### 3.2 为什么不用「加别名」「降 min_score」

| 备选方案 | 为什么不选 |
| --- | --- |
| 加单字别名「极」「将」 | `len(an) < 2` 直接跳过，代码层面无效 |
| 加短语别名「极和将」 | 跨 `\x01` 分隔符，实测无效（已还原） |
| 把「极」「将」放进 `WEAK_ALIASES` | 会让「极其无聊」「极度疲惫」里独立成段的「极」也参与匹配，**反而更危险** |
| 降低 `min_score` | 任务单明令禁止：会连带放大所有条目的误注入 |

### 3.3 为什么只对 `ban-ben-pai-zi` 生效

```python
if entry.get("slug") == "ban-ben-pai-zi" and _plate_context_hit(qn):
    total += PLATE_CONTEXT_SCORE
    return total
```

**硬编码 slug**，不改变其它任何 559 条的评分路径。这是「最小改动」的直接体现——全量审计数字不变（712 → 712）就是证据。

分数取 **16.0**：高于注入阈值 10.0，低于「整句正好是标题/别名」的 20.0（因为依赖两词共现，比直接叫名字弱一档）。
