# AstrBot 已加载插件审阅（2026-10-24，只读）

审阅对象是 Launcher 实例 `core/data/plugins` 的**已加载**插件，不是插件市场里的全部条目。依据当日启动日志、实例配置和生产插件钩子；未改启用状态。

| 插件 | 现状与用途 | 建议 |
|---|---|---|
| Miruku 本地知识注入、Miruku 元数据记录 | 分别提供限定私聊的知识块与观察证据 | 保留；C-15 实际消息命中仍待终验 |
| Proactive Chat | 项目已决定保留主动调度，当前 C-10 仍待修 | 保留，先修恢复与出站问题 |
| SoulMap 用户画像 | `on_llm_request` 将画像摘要加入 `system_prompt`，`max_notes_count=5` | 保留但限制大小与目标会话；DS-07 计入请求体量 |
| LivingMemory | 配置召回 `top_k=5`、会话窗口 50；当日日志反复提示缺 Embedding Provider，60 次重试后初始化失败 | **当前无效**。建议在 DS-07 取证后停用，待决定 embedding 服务和验证成本后再启用；不把它算作已具备长期记忆 |
| EmotionAI | 每轮追加认知上下文、两个 `<thought>` 样本及强制 XML 指令；样本里仍有“星绘”，与 Miruku 不符 | 高优先级审查，建议修正或停用；可能造成口吻污染与内部标记外泄。它每轮新增内容，但目前没有证据证明它造成 155 万 token |
| humanlike | 随机忽略当前开启，概率 10% | 建议关闭随机忽略，尤其不能漏接稀少的情绪袒露；其余拟人化功能按体验验收决定 |
| Group Chat Plus | `enable_group_chat=true`，`enable_private_chat=false`，记忆注入关闭；其 LLM 钩子对非本插件请求直接返回 | 目前单人私聊项目用处很小，建议先停用；不据此推断它造成本次私聊超长上下文 |
| Reply Directly | 主处理器仅匹配群消息，配置仍启用主动连续交互 | 单人私聊阶段可停用，避免未来误开群聊互动 |
| Qzone | QQ 空间功能，自动评论 cron 配置非空 | 当前陪伴主链路无必要；若没有明确的空间运营计划，建议停用，避免额外对外动作 |
| Self Iterative Core | 向模型注册读写文件、加载及卸载插件等工具 | 建议优先停用；自动改代码/插件不属于已定的陪伴能力，权限与稳定性代价高 |

**上下文上限**：插件无法改变模型服务端的 1,048,576 token 硬上限。长期记忆的正确作用是把旧信息存到请求之外，每轮只召回少量相关片段；若无限注入，它反而占用窗口。当前 `LivingMemory` 因缺 embedding provider 未就绪，故不能把这次 1,554,619 token 超限归因于它。`SoulMap`、`EmotionAI` 会注入，DS-07 应按组件量化后再判根因。

**执行顺序**：先让 DS-07 保存超限请求的长度证据并修复普通回复；再分批停用冗余插件，每次用同一测试私聊验证回复与人格。未做任何停用或配置修改；正式投放门槛不因精简插件而自动通过。
