# 危机告警规范 v4 复核（2026-10-22，Codex）

## 结论

C-11 的 **B 档失败终态方案通过**：`failed_final` 与 `suppressed` 分开，`failed_reason` 区分传输失败和目标校验失败，T13–T15、重启跳过及限流计数一致。A/B 整体状态机**暂缓编码**，还需补清下述一处 A 档首次发送失败路径。

## 必须补清：A 档首次发送失败后的时钟

`crisis-alert.md` §8.1 之二规定 A 档传输失败后为 `push_state=pending`、`resend_state=active`，并写“+15/+30/+45”；但 §7.5、§7.6 规定三个补发 slot 全从 `first_pushed_at`（首次**成功**推送时间）起算。首次发送未成功时 `first_pushed_at=null`，`next_resend_at` 也无法按该规则求出。此时启动扫描 §7.6 第 5 条可能把事件当作逾期补发、无限拾取，或永远不触发。

请明确区分 **首次成功前的传输重试** 与 **首次成功后的三次提醒补发**：前者用哪个持久化时间字段/退避规则、是否计入 `resend_count`、重启时如何恢复；首次成功后何时置 `first_pushed_at` 并启动 15/30/45 分钟三个 slot。增加“首次发送失败→重启→仍失败→首次成功→三次补发”的状态转移例。不得把 B 档失败带进这条重试路径。

## 次要措辞

`failed_final` 的释义“已尝试、未成功”不完全覆盖 `target_check` 拒发（校验不通过时根本不得尝试 QQ）。建议改成“未成功且按规则不再尝试/重试”，保持终态语义。
