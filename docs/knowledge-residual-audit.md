## 一、结论先说

1. **DS-02 报的 2.87% 口径有污染，不能直接引用。** 它把测试号会话算进去了。
   测试会话命中率 24.39%，真实会话 2.67%，差 9 倍。真实投放面对的是后者。

## 三、可复跑的分层与计数方法

脚本：`data/residual_audit.py`（只读）。

```bash
# 真实会话（默认，推荐）
<Launcher python> data/residual_audit.py --dump
# 两会话合并（DS-02 旧口径，用于对比）
<Launcher python> data/residual_audit.py --all
# 逐条看某一判定
<Launcher python> data/residual_audit.py --show 需人工判断
```

产出：`data/residual_audit.json`（统计）、`data/residual_audit.tsv`（前 12 字 + 条目 + 判定 + 命中词）、
`--all` 时另写 `data/residual_audit_all.json`。

**分层规则**（互斥，优先级从高到低）：

| 层 | 条件 |
|---|---|
| 敏感内容 | 命中的首位条目 `sensitive=true` |
| 明确求知 | 含疑问词（`[?？]|吗|呢|什么|啥|怎么|多少|哪个|哪儿|如何`）且（含语境词 或 命中词 ≥3 字） |
| 游戏混合话题 | 含语境词（`MUSIC_WORDS + GAME_WORDS + VRC_WORDS`） |
| 日常闲聊 | 其余 |

**判定规则（DS-03 重写过，见下）**：

| 判定 | 条件 |
|---|---|
| 需人工判断 | 没有字面命中词（靠 n-gram 或 tag 进来） |
| 不应注入 | 命中词在 `GENERIC_ALIASES`（日常高频词） |
| 不应注入 | 命中词在 `WEAK_ALIASES` 且 `clean_query` 后**没有独立成段** |
| 应注入 | 其余 |

### 为什么重写判据（这一段是 DS-03 的主要教训）

第一版判据用「命中词长度 ÷ 整句长度」当覆盖度，规则是
`cover < 0.5 且 len(term) <= 2 → 不应注入`。跑出 107 条「不应注入」，占命中样本 43%。

**这 107 条里绝大多数是假阳性。** 逐条看过，被这条规则打掉的是：

- 「八点半海斗」（覆盖率 2/5 = 0.4）
- 「我帮你跑刀」
- 「还在街霸是吗」
- 「你能帮我鸟加墓守吗」

这些恰恰是**真在聊那个话题**。短句里 2 字圈内术语覆盖率天然低，
而覆盖率低只说明对方在正常说话、顺手提了一句，不代表不该注入。

真正的区分不是覆盖率，而是**命中词本身是什么词**：

| 类别 | 例 | 真实语料词频 | jieba 词典频次 | 判定 |
|---|---|---|---|---|
| 圈内术语 | 海斗 / 街霸 / 出勤 / 跑刀 / 鸟加 / 改模 / 粥 / 撤离 / 斗魂 / oopz | 6–72 | 0–5 | 应注入 |
| 汉语常用词 | 性格 / 旋转 / 入坑 / 立绘 / 痛包 / 雷霆 / 辉夜 | 0–2 | 200–5000 | 不应注入 |

两条证据独立同向：真实语料里术语是高频话题词、常用词是偶发；jieba 词典里术语几乎查不到、
常用词都是常用字。所以判据改成查集合，不算覆盖率。

`data/residual_audit.py` 的 docstring 里记了这段原因，避免以后有人再改回覆盖率。

## 五、改了什么

只改了两处，都在 `knowledge/query.py`。

### 1. 新增 `WEAK_ALIASES`（`knowledge/query.py:151` 附近）

```python
WEAK_ALIASES = {"性格", "旋转", "入坑", "立绘", "痛包", "雷霆",
                "辉夜", "辉夜姬", "天爆"}

# 弱词的第二个放行条件：紧跟在一个动作词之后
WEAK_VERB_PREFIX = "打听放点练看上唱玩刷推"
```

规则：**弱词必须独立成段、或紧跟一个动作词，才算命中**。`clean_query()` 用 `SEP="\u0001"`
把停用词换成段分隔符，所以：

| 输入 | clean 后 | 判定 |
|---|---|---|
| 好像能旋转 | `好像能旋转`（一整段） | 不算 |
| 旋转怎么打 | `旋转\|打` | 算 |
| 并非痛包 | `并非痛包` | 不算 |
| 痛包怎么弄 | `痛包\|弄` | 算 |
| 今天爆率高会摸回来的 | `今天爆率高\|摸回来`（天爆横跨两词） | 不算 |
| 他在打天爆 | `打天爆`（不独立） | **算**（「打」是动作词） |

三处生效：标题分支（`title_n in WEAK_ALIASES` 时跳过标题分）、
标题「A / B」分段分支、别名分支。

**为什么不用 `GENERIC_ALIASES`（加进日常词集合）**：那个集合是「必须伴随音乐/游戏语境词才放行」，
而弱词的真提问往往没有语境词（「旋转怎么打」里没有「谱」「难度」）。加进去会把真提问一起杀掉。
实测把 6 个词直接塞进 `GENERIC_ALIASES`：修好 5 条误注入，但同时砍掉 9 条真提问。

**为什么需要「紧跟动作词」这条例外**：只要求独立成段会连带打死「他在打天爆」「我想听天爆」——
`clean_query` 把「他」「在」删掉后剩「打天爆」一整段，天爆不再独立。
实测只加独立成段规则时，这条会掉到阈值下。而「天爆」是圈内高频叫法，
真聊起来不认识比偶尔多注入一条歌更贵。动作词集合刻意取得窄
（`打听放点练看上唱玩刷推`）：「好像能旋转」的「能」、「并非痛包」的「非」、
「看到立绘脸红」的「到」、「干脆直接入坑邦邦得」的「接」都不在里面。

### 2. `辉夜`/`辉夜姬` 用同一机制但理由不同

它们不是汉语常用词，而是**常作为更长专有名词的一部分**出现（《超时空辉夜姬》是动画，不是东方角色）。
独立成段时照常命中：「辉夜姬」26.0、「辉夜」30.0、「辉夜姬是谁」20.0、「蓬莱山辉夜」31.67。
代价：「辉夜姬的符卡」这类粘连写法会失效——真实语料里没有这种写法。

### 3. 回归用例 93 → 113 → 120

新增 27 条，**正负成对**：

| 组 | 新增 | 作用 |
|---|---|---|
| 正例（排名边界） | 旋转怎么打 / 立绘是什么 / 痛包怎么弄 / 雷霆的话是什么 / 怎么入坑 / 你什么性格 / 辉夜姬是谁 / 蓬莱山辉夜 | 保证弱词独立成段时**仍然命中** |
| 正例（排名边界） | 他在打天爆 / 我想听天爆 / 天爆怎么打 | 保证弱词紧跟动作词时**仍然命中**（修订时补的） |
| 正例（排名边界） | 今天爆率高会摸回来的 / 大红是什么 / 你在干什么 | 保证误注入被换成了对的知识、以及口吻改写后仍命中（修订时补的） |
| 正例（排名边界） | 你打舞萌吗 / 你几岁 / 你唱歌吗 / 你什么段位 | 保证 self 人话问句命中**对条目**（第二轮补的，见第十五节） |
| 负例 | 好像能旋转 / 并非痛包 / 看到立绘脸红吗 / 我干脆直接入坑邦邦得了 / 什么雷霆封面 / 光是看外貌和性格也能看出来 | 保证弱词粘在句子里时**不命中** |
| 负例 | 什么意思 / 真的假的 / 你是格调 | 保证「别名 clean 命中」不溢出到非 self 主题（第二轮补的） |

成对是必须的。只测负例会退化成「把弱词整组禁掉」，只测正例会退化成「什么都注入」。
`data/regression_cases.json` 的 `meta.notes` 里写明了这条约束。

「天爆」那三条正例尤其重要：只加 `WEAK_ALIASES` 而不加动作词例外，
「他在打天爆」会被一起打死，而负例（今天爆率高）仍然会通过——
**没有这三条正例，坏改动也能全绿**。

### 模式一：约局/汇报状态时被科普（占比最高）

Oopz 27、海克斯大乱斗 20、街霸6 15、出勤 13、三角洲行动 11、大红/爆率 11、粥 10、改模 8、跑刀 6、鸟加 7。

共同特征：对方在**约时间、报进度、说自己在干嘛**，只提到游戏名或术语，没有问任何问题。
注入的内容全对，但插进对话里就是答非所问。

**这类不该靠改检索解决。** 检索只看得见一句话，看不见「他刚才已经说了三句海斗」。
可行的方向是运行期节流或按「是否在提问」降权——但那要真实投放后的数据，不能离线拍板。

### 模式二：日常词撞别名（7 条，全部修掉）

见第四节表格。已修的全部属「汉语常用词恰好是别名」或「两个字拼接后偶然撞上别名」，
修法就是第五节。最后一条「天爆」还额外补了一条知识，让它命中对的东西。

### 模式三：「你在干什么」（23 条，口吻问题）

命中 `self/平时做什么`，别名精确匹配，**检索层面是对的**。
但注入的内容原来是「Miruku 平时就在线陪着聊天…没有真人的日程」，
模型拿到它之后容易把回答写成自我介绍，而对方只是随口问一句。

**修订后已改（2026-10-22 晚，OTTO 指令）**：这条的 summary 和 detail 都重写了，
不再是「没有真人日程」的设定说明，而是「Miruku 也有自己的小日子：可能在喝牛奶、在打舞萌，
也可能就在发呆」。detail 明确要求「随口说一件手头的小事，一两句带过，不要写成自我介绍，
也不要解释『我是 AI 没有日程』」，同时保留「别编具体到能对上的细节」。

改后 `你在干什么` 仍然命中（45.47），但注入内容变成可执行的说法而不是设定说明。

### 「今天爆率高会摸回来的」：不是误命中，是知识库里缺一条

**这一条本来的判断是错的。** DS-03 初稿把它判成「误命中，修法代价大于收益」，

> 「今天爆率高会摸回来的其实是游戏三角洲行动的评价，指的是爆率高出大红这种，
> 摸回来的大红级别收藏品卖钱，赚回来之前的亏损。」

也就是说，对方在说**三角洲烽火地带的爆率/大红**，Miruku 该接的是这个，

**两步一起做才成立：**

1. **挡住误命中**：把「天爆」也加进 `WEAK_ALIASES`（`knowledge/query.py:151`）。
   它不是日常词，字也常见，但它是「今天」+「爆率」拼接后偶然出现的两字（今[天爆]率）。
2. **让动作词前缀放行**：新增 `WEAK_VERB_PREFIX = "打听放点练看上唱玩刷推"`，
   弱词紧跟动作词时仍算命中。否则「他在打天爆」会被一起打死——

3. **补知识**：`knowledge/src/games.json` 新增 `da-hong-bao-lv`

## 八、量化：注入落在哪里、有多长、重复多少

| 注入块长度 | min 58 / 中位 75 / 均值 80.0 / p90 109 / max 178 字符 |

**节流收益**（同一首位条目在 N 条消息内只注入一次）：

| 窗口 | 剩余命中 | 变化 |

| 5 条 | 215 | −7% |

## 九、仍无法自动判定的边界

这些情况机器判不了，运行期只能靠观察或人工回看：

1. **夸人 vs 游戏黑话同形**：「大王」「88boy」「我是 AI」这类，字面命中但意图是社交。
2. **同一个词在两种义上**：「手套」既是实物也是打舞萌装备；「牛奶」既是饮料也是 Miruku 的偏好。
   现在都判为可接受（语义相邻），但如果对方明确在说别的，就会显得跑题。
3. **专有名词包含关系**：《超时空辉夜姬》vs 东方角色辉夜姬已经用弱词规则挡住，
   但同类问题还会有（《明日方舟》vs 三国杀的「方舟」之类），只能逐案加。
4. **「提到了」不等于「想聊」**：模式一那一大类全靠这个，检索层面无解。
5. **反问、玩笑、引用别人的话**：`clean_query` 只看字面，识别不了语气。

## 十、推荐运行期观察字段

接入 AstrBot 后，建议至少记录下面这些，才能判断离线命中率与真实体验的关系。
**不记录聊天正文**，只记录元数据。

| 字段 | 类型 | 为什么需要 |
|---|---|---|
| `knowledge_injected` | bool | 这一轮到底有没有注入（判定的唯一依据，不要用「回复里提没提到」） |
| `knowledge_titles` | list[str] | 注入了哪几条，用于统计哪些条目在真实场景里反复出现 |
| `knowledge_score_top` | float | 首位分数，用于看阈值附近的实际分布 |

| `session_key_hash` | str | 会话标识（哈希，不存原始 QQ 号） |

**关键提醒**：这些字段只能说明「注入发生了没有、注入了什么」，

## 十五、修订记录（2026-10-22 夜，第二轮：别名 clean 命中）

第十四节之后又发现一个更根本的问题，与 OTTO 关于「Miruku 打舞萌、水平 w4」的拍板直接相关。

### 问题：self 条目的人话问句别名永远对不上

`clean_query()` 会把查询里的「你」「吗」当停用词删掉，但别名走的是 `normalize()`，
别名里的「你」「吗」原样保留。于是 `你打舞萌吗` clean 成 `打舞萌`，
而别名仍是 `你打舞萌吗`，`an in qn` 永远不成立。

实测后果（修前）：

| 输入 | 修前命中 | 分数 | 问题 |
|---|---|---|---|
| 你打舞萌吗 | `dian-wo`《"打舞萌会电我"》 | 38.40 | 答的是「打舞萌伤身」的梗，不是自己的水平 |
| 你什么段位 | `duan-wei-ren-ding` | 33.00 | 问的是水平，答的是玩法条目 |
| 你有R值吗 | `r-zhi` | 29.00 | 同上 |
| 你几岁 / 你多大 / 你生日 | `sheng-ri-nian-ling` | 7.00 | 阈值下，等于不注入 |
| 你唱歌吗 | `hui-chang-ge` | 7.00 | 同上 |
| 你住哪 | `bei-wen-zai-na` | 7.00 | 同上 |

也就是说，`self` 主题里所有「人话问法」的别名都是**失效的**——命中靠的是 n-gram 撞出来的
旁支条目，答非所问。

### 修法：别名 clean 命中（`knowledge/query.py` 别名循环开头）

别名的 clean 形式与 clean 后的查询**完全相同**时给 20.0（与「查询正好等于标题」同档），
并置 `strong_hit = True`：

```python
ac = clean_query(alias)
alias_clean_hit = (
    entry.get("topic") == "self" and bool(ac) and ac != an and qn == ac
)
```

分支顺序变为 `if alias_clean_hit: ... elif qn == an: ... elif an in qn: ...`。
原有门禁照旧：clean 后退化成 `GENERIC_ALIASES` / `WEAK_ALIASES` 的别名不算。

### **必须限定 `self` 主题**（这条是补丁的核心约束）

第一版没限定主题，全量审计立刻多出 24 条命中，其中 3 类是新误注入：

| 输入 | 错误命中 | 分数 | 原因 |
|---|---|---|---|
| 什么意思 / 这意思吗 | `he-yi-wei`《何意味》 | 29.0 | 别名「什么意思」clean 成「意思」 |
| 真的假的 | `hui-ying-de`《会赢的》 | 20.0 | 别名「真的假的」clean 成「真/假」 |
| 你是格调 / 有格调 | `azure-vixen`《Λzure Vixen》 | 25.0 | 别名「有格调」clean 成「格调」 |

语料证据：`什么意思` 4 次、`真的假的` 4 次、`格调` 4 次，**全部是日常用法**。

根因是两类别名的性质不同：`self` 的别名是**人话问句**（clean 后仍是明确指向），
其他主题的别名是**名词叫法**（clean 后常退化成一个常用词）。所以限定 `self` 不是保守，
是这条规则的适用边界。
