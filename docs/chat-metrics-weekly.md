# 聊天质量周报

用户需求（m09447）：「在投放之后我希望他能在和来世不断的对话中能优化对话方式」，
选的是 B 方向「更会聊」——可量化。本文件说明每周怎么用数据做判断。

前置：`astrbot_plugin_miruku_metrics` v0.1.0 已在线上（2026-11-02 部署），
采集逻辑与三个数据陷阱见 `docs/chat-metrics-20261102.md`。

---

## 一、每周跑一次

```bash
bash /opt/miruku/server/metrics-report.sh --days 7
```

输出示例：

```
── QQ 10000002 ──
  采样 12 次，最近一次 2026-11-09T21:30:00+08:00，会话共 186 轮
  最近 5 次中位数：
    对方说了几句                 14
    她说了几句                  16
    话轮比（她/对方）              1.14     偏高=她话多；偏低=她冷淡
    最长自说自话                 2        >=3 说明连发几句都没人接，是冷场信号
    主动消息被回复率               0.65     越高越好；<0.4 说明主动消息时机或内容不对
    对方平均字数                 18.0     突然变短可能是在敷衍
    她平均字数                  14.0     太长像客服，太短像敷衍
```

## 二、五个判断阈值

看「最近 5 次中位数」这一栏，不是看单次：

| 指标 | 健康区间 | 越界说明什么 | 下一步 |
|---|---|---|---|
| `turn_ratio` | 0.6 – 1.4 | >1.8 她太话痨在自问自答；<0.5 她太冷淡 | 看 persona 的「对话不要只停在他给的话头上」这段是否被忽略 |
| `max_bot_streak` | ≤2 | **≥3 = 冷场**（连发 3 句以上没人接） | 检查主动消息时机/内容，看是不是她自己硬撑话题 |
| `proactive_reply_rate` | ≥0.6 | **<0.4 = 主动消息接不住** | 主动消息的开口方式不对，或时机（她可能在忙）不好 |
| `user_avg_len` | 稳定或上升 | 突然掉到个位数 = 在敷衍 | 对照那几天的对话看是不是她一直在问、对方只答 |
| `bot_avg_len` | 10 – 30 | >50 像客服；<8 像敷衍 | 太长要压 persona 的表达欲，太短是没内容 |

## 三、什么情况才动 persona

**只有同时满足才建议改**（单周单指标越界不改，避免噪音驱动）：

1. 指标越界**连续两周**；
2. 抽样看了原始对话，确认不是特殊情况（比如那周她在考试、在忙）；
3. 能定位到 persona 的**具体哪一句**导致这个行为。

改的时候必须走 `server/deploy-persona.py`（唯一生效路径），改前备份、改后回读字数验证，
并写进 WORK_LOG 注明「因为什么改的」。**这三步不能省——persona 有三份来源互不相同，
手改容易改到不生效的那份。**

## 四、现在已知的三个「不是问题」

避免每周重复分析：

1. **`proactive_reply_rate` 在关系早期天然偏低**——刚加好友时对方不熟，主动消息不回是正常的，
   不一定是内容问题。看趋势不看绝对值。
2. **`max_bot_streak` 会在她忙的时候虚高**——比如她在上课，三条主动消息都没回，
   streak 就到 3。要和「那几天她有没有整个人消失」交叉看。
3. **`user_avg_len` 会被图片消息拉偏**——纯图片已经过滤掉，但「发图+一两个字」仍然偏短，
   不代表敷衍。

## 五、长期可做但没做的

按价值排序：

1. **主动消息实时指标**——现在指标只在收到私聊时采集，所以「连发 N 条没人理」要等对方下次
   说话才被记录。要做实时得在主动消息发送钩子里也采一次快照（`@filter.after_message_sent`）。
2. **按话题分桶**——现在所有对话混在一起算，看不出「聊舞萌时她状态好、聊日常时冷场」。
   需要给每轮对话打话题标签，成本高。
3. **A/B 对照**——同一段 persona 改动的效果要靠前后对比，但如果中间还改了别的就没法归因。
   真要做得冻结其他变量，目前不现实。

这三件都**没有**做，也没写进代码，只在这里记着。
