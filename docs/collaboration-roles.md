# Miruku 三方协作分工（2026-10-21）

本文件规定从现在起的工作归属。历史改动保留；每次开工仍先读 `WORK_LOG.md`（顶部「当前状态」）和 `docs/otto-decisions-20261024.md`。`docs/handoff.md` 已于 2026-10-24 降级为历史快照，不再作为事实来源。Miruku 只服务来世一人，但以稳定和不打扰为先，画像、主动调度和插件化都保留。

## 一个负责人、两个评审视角

| 角色 | 主责与可直接修改的范围 | 交给其他人的事项 |
| --- | --- | --- |
| OTTO（项目主） | 决定何时开放真实联系人、陪伴效果的判断标准、人格与情绪边界的最终取舍 | 无需协调日常技术细节；只看需要拍板的方案及证据 |
| Codex（工程负责人、上线整合） | AstrBot/NapCat、脚本与插件、运行配置、观察与备份、故障排查、测试和上线验收；负责把已审定内容接进运行实例 | 人格/口吻改动先请 WorkBuddy 审阅；知识事实问题交 DeepSeek |
| WorkBuddy（产品体验负责人） | `persona/`、主动消息语感、情绪边界、真实对话体验评审；提出陪伴效果度量方案 | 代码和运行配置交 Codex；知识条目事实交 DeepSeek |
| DeepSeek（知识与回复质量负责人） | `knowledge/src/`、知识检索质量、事实核验、测试对话的回复分析；可提出提示词修改草案和验证样例 | `prompts/system.txt` 的定稿由 WorkBuddy 审阅、OTTO 认可；运行接入、部署和 QQ 验收交 Codex |

## 共用文件和运行实例的规则

1. `prompts/system.txt` 是共同接口。任何一方发现回复问题，先在 `docs/` 记录原话、期望行为、拟改的最小段落与复测样例；WorkBuddy 审阅体验与情绪边界，Codex 检查与运行配置的冲突。涉及已定人格核心决策时由 OTTO 拍板。不要三方同时直接改提示词。
2. `persona/` 由 WorkBuddy 主笔；`knowledge/src/` 由 DeepSeek 主笔；`plugins/`、启动脚本和运行配置由 Codex 主笔。跨界发现问题时在 `WORK_LOG.md` 写清证据和建议，交给主责人处理。
3. **只有 Codex 负责向 AstrBot 实例部署和修改 QQ 发送配置**，并记录改动前状态、变更、回退方法和验收结果。DeepSeek 与 WorkBuddy 可做离线分析及只读核查，不单独部署。
4. 所有 QQ 测试优先发测试号。来世已受邀做过普通私聊实测，但这不等于批准日常投放或主动消息；切换主动收件人和正式开放时点由 OTTO 决定。
5. `WORK_LOG.md` 继续作为唯一进度同步板：开工先读；每项实质工作完成后，在“最新进展”顶部追加日期/责任人/做了什么/影响/下一步，并更新当前状态。若发现其他人刚改了同一文件，先读新记录再继续。

## 交付给 OTTO 时只报三件事

每人只报：**完成了什么（附证据）／还存在什么风险／需要 OTTO 决定什么**。不能把“已写代码”“本地探针通过”当成真实 QQ 已验收，也不能把人工扫码后的重连当成无人值守登录成功。
