# Miruku 交给来世前的上线检查

更新时间：2026-10-20。此处记录当前实例的只读核对结果；上线配置变更后需重新验收。

## 必须先完成

1. **限定收件范围（已配置，真实非目标消息仍待验）**：AstrBot 白名单已设为测试私聊和来世私聊两个会话 ID，管理员私聊与群聊豁免均关闭。已用当前版本 `WhitelistCheckStage` 对两条允许、其他私聊及群聊做隔离验证；尚未从真实非目标 QQ 发消息验收。上线后应移除测试私聊，只保留来世。
2. **分阶段切换主动收件人**：目前 proactive_chat 的 `friend_settings.session_list` 只有一个测试会话，不包含来世；群主动消息关闭，自动触发关闭。先让来世的普通私聊回复通过真实 QQ 验收，再切换主动会话，并复核 3–6 小时间隔、1–8 点免打扰、未回复最多 1 次和实际收件人。
3. **真实私聊链路（普通回复已验，主动仍待验）**：目标 QQ 已有 4 条入站、3 条普通出站和 2 条首次回复间隔；来世本人受 OTTO 邀请实测三条并收到回复，普通私聊链路已验收。WorkBuddy 指出的主动消息钩子缺口已用现有平台流水的只读轮询补上，并通过本地合成事件验证；真实目标主动消息仍待上线后验收。
4. **重启恢复（AstrBot 通过，NapCat 需人工验证）**：2026-10-20 用户登录后任务记录显示 AstrBot 16:10 启动；OTTO 确认开机恢复检查消息到达测试 QQ。NapCat 登录任务能拉起 QQ，但快速登录态失效并周期刷新二维码；OTTO 后来完成手机登录，OneBot 重连且测试 QQ 再次收到检查消息。自动入口改为无乱码控制台并在新二维码出现时尝试打开图片。整机重启后的无人值守登录不能标为通过，QQ 安全验证需人工完成。
5. **本地备份（已完成一次）**：`backup_runtime.py` 用实例 Python 对 AstrBot 与观察库执行 SQLite 在线备份和完整性检查，并保存主动任务文件；结果位于被 `.gitignore` 忽略的 `data/backups/`。备份包含私聊数据，按本机私有数据保管。

## 交付方式建议（待 OTTO 确认）

- 第一阶段让来世知道 Miruku 是机器人，先只开放普通私聊，观察口吻、误回复和记录链路；确认后再开放主动消息。主动调度能力保留，不删减。
- “陪伴效果好”的指标尚未拍板。建议先讨论三个维度：打扰是否过量、袒露时是否被接住、对方是否愿意自然续聊；原始事件继续保留未知模式值，不用关键词推断成真实触发。
- 危机资源和人工接管方式应由 OTTO 确认；不填写未经确认的电话或联系人。
