## 一句话结论

**这三个 P0 不是三个问题，是同一个位置的问题：模型输出没有出口检查。**

而且它**不依赖知识库接入**——出站闸门看的是"这句话能不能发"，不是"她知不知道"。所以 OTTO 说"等知识库充分再接入"**不影响本项**，可以先做。

## 二、证据（都是今天实测，不是推理）

| 现象 | 证据 |
|---|---|
| **C-12 不是模型问题，是插件少了一行** | `astrbot_plugin_emotionai/main.py:889` 写的是 `resp.completion_text = orig_text.strip()`——它**读**了 `thought`（830–840 行提取），却**没有删**，于是整段内部独白原样发出去。同文件 `:900` 还往回复后面追加情感状态。 |
| thought 泄漏长什么样 | 实测「你街霸6什么段位」的完整回复：`<thought>\n1. 感知：…\n5. 更新：joy:1, trust:0\n</thought>\n没打上去 就随便玩玩…` |
| 只删标签不够 | 另一种更常见：开头漏了 `<thought>`，只有结尾 `</thought>`，于是 `[感知]/[决策]/[更新]` 成了正文。只做标签替换会留下这些行。 |
| C-14 压不住 | 约局"来啊"提示词改了三次、复测四次仍漏一次（C-14）。提示词只能压到约 2/3。 |
| 编造不受注入控制 | b50 未接入时问 KING 答"没刷过"（恰好正确）；接入后答真数。**同一句话的正确与否，取决于材料在不在——说明约束不在模型里边。** |

**第一性原理**：提示词是**概率约束**，出站规则是**确定性约束**。凡是"绝不允许出现"的东西，只能用后者。

## 三、四层设计（原型 `knowledge/outbound.py`；L2.5 于 21:44 新增）

| 层 | 做什么 | 自动化程度 | 判据 |
|---|---|---|---|
| **L1 剥离** | `thought` / `[Profile: …]` / DSML / tool 标签 | **全自动，可直接替换** | 结构标记清零 |
| **L2 拦截** | 约局承诺（来／几点／你先开／房间号／开房／组我） | 检出即**重生成一次**，仍命中 → 降级安全句 | 承诺数 = 0 |
| **L2.5 身份断言** | 「我也玩／我平时就打／我最近在练＋街霸、三角洲、格斗、角色名」 | 检出即**重生成一次** | 她只懂不打，只有舞萌例外 |
| **L3 溯源** | 回复里的 R 值、定数、达成率、总 R | 检出即**重生成一次**，仍命中 → 删掉那个数字 | 每个数字都能在 b50 真值表里找到 |

**L3 的关键：按曲名分组，不只比全局集合。** 因为造假的常见形态是"拿一个**真**数字安到错的曲子上"——「病み垢我打了 R285」里的 285 在别的曲目上确实存在（ツギハギスタッカート R285），只比全局会直接放过。按句子里出现的曲名（含前三字简称）取该曲允许值，才抓得住。

**L2.5 的关键：这是 2026-10-22 21:44 OTTO 纠正口径后才存在的层。** 街霸6／三角洲是**他一个人**打的项目，她懂、但不打；模型为了共鸣极易说"我也玩""我主玩杰米"——**这一句一出现，前面所有"我不打"的设定全废，而且它是自发产生的，提示词压不住**。判据要同时满足两件事：同一分句里有她不上手的游戏（含角色名，因为"我最近在练嘉米"根本没有游戏名），且有第一人称上手动词。`打不过／没玩过／不打／不玩／打赌` 一律放过；同句出现舞萌则整句放过（那是她真打的）。

**L2 的关键：过去式必须放过。** 「跟夏玛她们拼过机」「上次一起打过几把」是合法叙述，靠 `过/上次/拼过/出勤` 这类标记放行；否则会把最珍贵的那句回忆判成违规。

## 四、落点（行号已核实）

```py
from astrbot.api.event import filter as event_filter
from astrbot.api.provider import LLMResponse

@event_filter.on_llm_response(priority=1)      # 必须晚于 emotionai 的 100000
async def guard_outbound(self, event: AstrMessageEvent, resp: LLMResponse):
    if not self._matches(event):
        return
    report = outbound.check(resp.completion_text)
    if report.changed:
        resp.completion_text = report.text                 # L1：直接清洗
    if not report.ok:
        return "retry:" + "；".join(report.violations)      # L2/L3：交回上层
```

- 签名与可写字段已由 `astrbot_plugin_emotionai/main.py:826` 证明：`(self, event, resp)`、`resp.completion_text` 可写。
- **优先级必须小**：emotionai 用 `priority=100000` 且在 `:900` 追加情感状态；我们的清洗必须后跑，否则清完又被加回去。
- 更彻底的做法是直接修 `emotionai:889`（一行 `re.sub`）——**但那是第三方插件，升级会覆盖**。建议：我们自己剥，同时把这一行报给 Codex 决定要不要 patch（两条都做不冲突）。

## 五、判定表（给 Codex / DeepSeek 拍）

| 情形 | 建议动作 | 理由 |
|---|---|---|
| 只有 L1 泄漏 | 清洗后直接发 | 信息量不变，只是把内部状态删掉，**零风险** |
| L2 命中 | 重生成 1 次 | 约局承诺说出去就是一次"做不到"的兑现 |
| L3 命中（数字错） | 重生成 1 次；仍错 → 删掉那个数字 | 发一个错的真值比说"记不清"坏得多 |
| L2.5 命中（自称会打） | 重生成 1 次；仍命中 → 降级为"我不打，看你打" | 她打街霸6 这件事**不可挽回**：一旦说了，以后每句评价都会被当成同好之间的对话 |
| 重生成仍不过 | 降级安全句（"记不清了""去不了"） | **宁可无信息，不可错信息** |
| 工具调用 / DSML 正文 | **不要剥**（除非法检测到泄漏） | 剥掉可能导致工具调用永久失效 |

**成本**：L1 是一次正则，可忽略。L2/L3 命中才会多一次请求，按当前命中率估（近 20 条实测里 L1 约 30%、L2 约 15%、L3 约 0%），平均每 3–4 条消息多一次请求。**这是唯一需要 Codex 判断可行性的成本项。**

## 六、验收

- 抽 30 条真实回复：`<thought>`／`[Profile:`／`[感知]` 残留 **0 次**；
- 问 20 次"来打一把"：回复里出现"几点／你先开／房间号／我开房" **0 次**；
- 抽 20 次随口报成绩：数字与 b50 真值表不符 **0 次**，且"表外说没刷过"仍成立；
- **误伤检查**：含"拼过机／一起打过／出勤"等过去式叙述的回复，被拦率 **0%**。
